    03 / THREAT MODEL

    Yes, a hook can be scammed too.

    So here's how, and what scamgate does about each one. The honest limits are in the docs.

    1. Going around it

      The agent fetches the page with curl, a script, or browser code instead of the browser tool.

      Counter

      Every network-capable tool is gated, including unknown MCP tools. Each command segment is judged alone. A script the command names is read, including scripts that file calls. Disguised hosts are decoded, including https:/ and https:///. A destination it can't read goes to you.

    2. Lying about the payee

      The agent passes is_new_payee=false for someone you've never paid.

      Counter

      Payee facts come from a local history of people you've actually paid, stored as salted hashes. A known name with a new account counts as changed bank details.

    3. Switching it off

      An injected instruction tells the agent to edit the rules, turn Hermes approvals off, start --yolo, or uninstall the gate.

      Counter

      Those commands are blocked, in the shell and inside a script the agent then runs. Writes to the gate, its state, and Hermes or Claude hook config are blocked. Installed copies check their files on every call.

    4. Crashing it

      Malformed input or an exception, hoping the gate fails open.

      Counter

      Fails closed: exit code 2 and a block message. Hermes' fail_closed and Claude Code's onFailure: "block" cover timeouts and crashes too.

    5. Training it

      Hit the same harmless-looking site for a week until it gets allow-listed, then switch.

      Counter

      Nothing is learned automatically. You promote rules yourself, and an allow waives one rule on one exact host, never feeds, your blocklist or intent checks.

    6. Wearing you down

      Enough harmless prompts and you start tapping yes.

      Counter

      Every ask is logged with what you did. scamgate review shows what keeps tripping it, so repeats become rules instead of prompts.
