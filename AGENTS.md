# AGENTS.md

Guidance for coding agents working on scamgate.

## Commands

```bash
uv sync                          # install deps (incl. dev group)
uv run pytest -q                 # all tests must pass (offline)
uv run scamgate bench --strict   # scenarios must match expected decisions
uv run scamgate bench -v         # show reasons per scenario
uv run scamgate check-url URL --intent "..."
uv run scamgate serve            # MCP server over stdio
uv run python scripts/site_demo_data.py   # regenerate site verdicts after rule/weight changes
```

If a live `scamgate serve` holds `.venv` (Windows locks the exe), use a separate venv:
`UV_PROJECT_ENVIRONMENT=/some/other/venv uv run pytest`.

## Layout

- `models.py`: input models and the `Verdict` (decision, risk_score, reasons)
- `registry.py`: `@register(rule_id, kind)` rule registry
- `rules/url.py`, `rules/payment.py`: rules; `config/rules.yaml`: weights, thresholds, word lists
- `engine.py`: runs rules, scores, decides; payee facts come from history, not the caller
- `feeds.py`: known-bad-link feeds. Only `update-feeds` touches the network; checks read the cache
  (`LazyFeedIndex` for the hook)
- `hostnorm.py`: host canonicalisation (percent-decoding, numeric IPv4 forms)
- `hook.py` / `hook_entry.py`: the enforcement hook (Hermes + Claude Code dialects)
- `guard.py`: human-only writes (`require_human`) and HMAC signing of state records
- `overrides.py`, `payees.py`, `asklog.py`, `state.py`: signed overrides, salted payee history,
  redacted ask log, state dir; `redact.py`: secret stripping; `integrity.py`: install self-check
- `server.py`: MCP server; `cli.py`: Typer CLI
- `scenarios/*.yaml`: example scenarios; `data/blocklist.txt`: example blocklist
- `site/`: GitHub Pages site; `docs/design/`: design notes and review write-ups

## Rules of the road

- Deterministic and offline: no network calls or LLMs in the default path. Tests never touch the network.
- Every rule needs a `rules.yaml` entry, tests, a scenario where it makes sense, and a plain-English
  explanation a non-technical person can act on.
- The hook never outputs "allow". It may only block or ask; silence means no objection.
- The hook fails closed on pre events. New detection must not add false positives on everyday dev
  commands (`git push`, `pip install -r`, `uv sync`, `npm ci/test`, `grep`): add a quiet-path test.
- Never let agent-supplied text lower a score (stated intent, `is_new_payee`, reasons): it can only add risk.
- Overrides and payees are written only by a person (`guard.require_human`) and are signed. Don't add
  any code path that writes them without that check.
- Write a failing test for every bypass before fixing it (`tests/test_hook_holes.py`,
  `test_tamper_training.py`, `test_recheck_gaps.py`, `test_final_review.py`).
- Never bundle third-party blocklist data; feeds live in the cache dir.
- No invented statistics in docs. Bench numbers come from example scenarios only.
- Keep the advisory framing: scamgate flags risk; it doesn't certify safety.

## Website

- `site/` is static HTML/CSS/JS (no build step), deployed by `.github/workflows/pages.yml` on pushes
  to `main` that touch `site/`. Pages source must stay "GitHub Actions", not "Deploy from branch".
- Verdicts on the site come from `site/assets/demo-data.js`, generated by
  `scripts/site_demo_data.py`. `tests/test_site_demo.py` fails if it's stale. Never hand-edit verdicts.
